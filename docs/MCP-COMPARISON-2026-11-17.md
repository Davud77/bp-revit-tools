## Реализовано в этом этапе

1. **Ограниченный вход:** до 64 активных TCP-клиентов, до 32 ожидающих команд. Избыток очереди получает ответ с исходным request ID и признаком ошибки до исполнения. Превышение лимита подключений закрывает сокет без приёма команды.
2. **Чтение до выделения большой памяти:** максимум 1 MiB вместе с delimiter, строгий UTF-8, незавершённый frame отклоняется. Чтение и отправка ограничены 10 секундами каждое.
3. **Асинхронное ожидание:** TaskCompletionSource с асинхронными continuation вместо ManualResetEventSlim.Wait на работнике пула. Сокет проверяется на отключение раз в 100 мс; результат будит ожидание немедленно.
4. **Отмена и остановка:** отменённые места освобождаются даже при занятом Revit; истёкшие запросы проверяются монотонными часами до начала API-выполнения. Очередь принадлежит экземпляру сервиса, Stop прекращает приём, освобождает очередь и закрывает соединения. Исход уже начатой записи при потере ответа может быть неизвестен: автоматических повторов нет.
5. **Порции API-вызовов:** максимум четыре команды за ExternalEvent, между командами проверяется бюджет 100 мс. Остаток поднимается из Idling. Одна длительная атомарная API-операция не прерывается по этому бюджету.
6. **Большие ответы Node:** поиск delimiter только в новом фрагменте и буфер с геометрическим ростом вместо повторного сканирования всей строки; предел 8 MiB сохранён. Некорректный UTF-8 не превращается в заменяющие символы.
7. **Каталог:** поисковый текст нормализуется при регистрации; JSON Schema строится один раз при первом запросе. Выдаётся отдельный объект схемы, чтобы изменение ответа не повредило следующий вызов. Проверка Zod при каждом исполнении остаётся.

Ключ `bp_revit_ai`, имена и аргументы tools, порт, каталог `%LOCALAPPDATA%/BP.Revit.AI`, preview/apply, привязка планов и общий установщик сохранены. Новых предметных команд в этом этапе нет.

## Следующие приращения

Порядок: задания с устойчивым результатом и явным состоянием → составной preview/apply и один Undo → обязательные постусловия → связные MEP-маршруты и пакетный выпуск. Каждое приращение должно получить собственную проверку на копии RVT; все они остаются открытыми в [дорожной карте](MCP-ROADMAP.md). Текущий этап закрывает конкретные дефекты ядра, но не означает достижения полного паритета со всеми продуктами.

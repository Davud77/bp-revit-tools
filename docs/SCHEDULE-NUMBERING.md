# Нумерация спецификаций

Команда BotPlus RT → Спецификации → Нумерация работает с открытой активной спецификацией проекта Revit 2026.

## Поведение

- Выбор текстового или целочисленного параметра экземпляра; по умолчанию ADSK_Позиция, если он есть. Одинаковые имена различаются ID определения.
- Начальный номер — 1, допускается целое неотрицательное значение.
- Порядок берётся из таблицы Revit, а не из коллектора или сортировки ID.
- В сгруппированной строке доступные элементы получают общий номер. Режим «Для выделенных элементов» меняет только элементы из исходного выбора; остальные сохраняют значения.
- Отсутствующий, read-only или не принимающий значение параметр пропускается. Номера успешных строк идут без разрывов. Итог сообщает число элементов, строк и пропусков, а также первые ошибки.
- После commit значения перечитываются. Неподтверждённый итог откатывается внешней группой. Успешный запуск — один Undo.
- Отмена окна не меняет модель.

## Сопоставление строк

Чтение выполняется в откатываемой TransactionGroup. Временный shared-параметр содержит ID элементов; копия спецификации сохраняет native sort/filter, раскрывает экземпляры и показывает служебную колонку. Для группированной таблицы предполагаемое членство по параметрам сортировки дополнительно проверяется на свёрнутых строках Revit. Пустое/неоднозначное соответствие останавливает операцию до записи номеров.

Временные binding, значения и копия спецификации откатываются. Исходный путь SharedParametersFilename восстанавливается в finally, временный файл удаляется. Состав и оформление пользовательской таблицы не меняются.

Основания API: [IsItemized в Revit 2026](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/10fc3753-29a0-8b1a-2f21-77f2634a4b9f.htm), [обсуждение Autodesk о сопоставлении строк и временной колонке ID](https://forums.autodesk.com/t5/revit-api-forum/get-element-of-viewschedule-gettabledata-row/td-p/5907290). Наличие документированного подхода не заменяет натурную проверку текущей реализации.

## Ограничения первой реализации

Обычные спецификации проекта. Исключены revision/key/material takeoff, embedded schedules, linked files и schedules filtered by sheet. Параметры типа не предлагаются: они могли бы изменить элементы вне выбранного набора.

Вычисляемые/комбинированные поля группировки не поддерживаются. При несовпадении сырой группировки и фактических строк (например, из-за округления) команда отказывается от записи. Если нельзя создать/заполнить временный параметр или не все элементы сопоставлены однозначно, нумерация отменяется. Для worksharing отдельно требуется проверка владения; открытый чужой проект не используется как тестовый.

## Проверки

Выполнены: сборка .NET 8 с Revit 2026 references; ScheduleNumberingChecks (порядок, группы, selection, readonly, пустой результат, дубли/overflow); HostChecks (панель и отключение); ScheduleUiChecks (параметр по умолчанию, значение 1, доступность флажка, кнопки, светлая/тёмная темы). PNG находятся в Выходные данные/Проверки/ScheduleNumbering.

Натурная проверка **ещё не выполнена**. Подготовлен ScheduleNumberingValidationCommand: в Revit через runner внешних команд он создаёт собственный несохранённый проект, три стены и спецификацию, проверяет native row order по длине, общую/выборочную/сгруппированную нумерацию, отсутствие служебных параметров/спецификаций и восстановление SharedParametersFilename; закрывает свой документ без сохранения. Текущий пользовательский проект не изменяет.

Перед закрытием задачи дополнительно проверить в Revit: окно/отмену, текст/целое, недоступный параметр среди доступных, native сортировку и фильтры, скрытые поля, одинаковые значения сортировки, частичный выбор группы, отказ вычисляемой группировки, Undo и сохранение/reopen. Нужна копия рабочей спецификации и отдельная workshared-модель. Сборка и policy-тесты не дают статуса live-tested.

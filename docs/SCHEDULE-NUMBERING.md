# Нумерация спецификаций

Команда BotPlus RT → Спецификации → Нумерация работает с открытой активной спецификацией проекта Revit 2026. Та же кнопка «Нумерация» (панель BotPlus RT) появляется на контекстной вкладке Revit «Изменить спецификацию/количество», пока активна спецификация, и убирается при переходе на другой вид. Порядок работы: открыть спецификацию, при необходимости выделить строки, нажать «Нумерация», выбрать параметр, начальный номер и «Для выделенных элементов».

## Поведение

- Оба списка следуют порядку «Поля в спецификации», включая скрытые поля. Для записи доступны редактируемые текстовые и целочисленные поля экземпляра. По умолчанию выбирается ADSK_Позиция, если она есть.
- Начальный номер — 1, допускается целое неотрицательное значение.
- «Поле для сортировки» сравнивает значения ячеек по возрастанию. Доступны расчётные и комбинированные поля, количество и итоги сгруппированных строк. Числовые значения сравниваются как числа, текст по текущей культуре без учёта регистра, пустые ячейки идут первыми. Равные значения сохраняют исходный порядок. По умолчанию выбирается ADSK_Единица измерения, затем «Единица измерения», затем «В порядке строк спецификации».
- «Очистить» очищает выбранный параметр для записи только у исходно выделенных элементов активной спецификации, независимо от флажка выборочной нумерации. Без выделения кнопка недоступна. Текст становится пустым; для целого вызывается ClearValue, если Revit допускает пустое значение. Ноль не подставляется. Если параметр отсутствует, недоступен, не допускает пустоту или значение восстановлено апдейтером после commit, очистка целиком откатывается. Один Undo.
- В сгруппированной строке доступные элементы получают общий номер. Режим «Для выделенных элементов» меняет только элементы из исходного выбора; остальные сохраняют значения.
- Отсутствующий, read-only или не принимающий значение параметр пропускается. Номера успешных строк идут без разрывов. При полном успехе итоговое окно не показывается; при пропусках выводятся количество и доступные причины. Ошибки, останавливающие операцию, остаются видимыми.
- После записи значения перечитываются. При расхождении команда показывает ID элемента, параметр, ожидаемое и фактическое значение и откатывает операцию. Значения, общие для нескольких экземпляров группы модели, пропускаются с указанием причины. Запуск с изменениями даёт один Undo.
- Отмена окна не меняет модель.

## Сопоставление строк

Чтение выполняется на временной копии в одной откатываемой транзакции. Для меток используется доступное текстовое поле экземпляра, если оно не участвует в сортировке и фильтрах. Приоритет у выбранного поля для записи, затем проверяются остальные поля таблицы. Если безопасного поля нет, создаётся временный общий параметр. Для свёрнутой спецификации без полей сортировки копия не нужна: все её элементы составляют одну строку.

По умолчанию копия сохраняет исходные фильтры, порядок и зависимости формул. В режиме «Для выделенных элементов» сначала находят пересечение выделения с элементами активной спецификации. Только эти элементы получают служебные метки, а копия фильтруется по ним. Количество и итоги отражают выбранный набор. Если Revit не допускает фильтр по метке, команда использует исходные фильтры, а затем оставляет выбранные элементы в сопоставленных строках.

Сначала читается таблица в её исходном состоянии. Если каждая строка уже однозначно показывает ID элемента, этап разворачивания не нужен. Когда строка содержит несколько элементов, команда использует столбец «Количество» и развёрнутую таблицу для сопоставления. Метки меняются только для строк с несколькими элементами. Сопоставление подтверждается по свёрнутой таблице, затем читается выбранный столбец сортировки. Если разбиение по количеству не подтверждается, проверяется разбиение по тексту полей сортировки.

Копия, значения меток и временный параметр откатываются. При создании общего параметра исходный путь SharedParametersFilename восстанавливается, служебный файл удаляется. Контекстная кнопка восстанавливается на вкладке спецификации проверкой активного вида в Idling с интервалом не чаще 250 мс.

Основания API: [IsItemized в Revit 2026](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/10fc3753-29a0-8b1a-2f21-77f2634a4b9f.htm), [обсуждение Autodesk о сопоставлении строк и временной колонке ID](https://forums.autodesk.com/t5/revit-api-forum/get-element-of-viewschedule-gettabledata-row/td-p/5907290). Наличие документированного подхода не заменяет натурную проверку текущей реализации.

## Ограничения первой реализации

Обычные спецификации проекта. Исключены revision/key/material takeoff, embedded schedules, linked files и schedules filtered by sheet. Параметры типа не предлагаются: они могли бы изменить элементы вне выбранного набора.

Для вычисляемых и комбинированных полей фильтрации или сортировки используется временный общий параметр. Если однозначно сопоставить элементы со строками не удаётся, нумерация отменяется. Для worksharing отдельно требуется проверка владения; открытый чужой проект не используется как тестовый.

## Проверки

Выполнены: сборка .NET 8 с Revit 2026 references; ScheduleNumberingChecks (порядок, группы, selection, readonly, пустой результат, дубли/overflow); HostChecks (панель и отключение); ScheduleUiChecks (параметр по умолчанию, значение 1, доступность флажка, кнопки, светлая/тёмная темы). PNG находятся в Выходные данные/Проверки/ScheduleNumbering.

Натурная проверка **ещё не выполнена**. Подготовлен ScheduleNumberingValidationCommand: в Revit через runner внешних команд он создаёт собственный несохранённый проект, стены и спецификацию, проверяет native row order по длине, общую/выборочную/сгруппированную нумерацию, отсутствие служебных параметров/спецификаций и восстановление SharedParametersFilename; дополнительно проверяет скрытое поле сортировки по убыванию, несколько групп с повторяющейся длиной, заголовками/итогами и повторное чтение после отката; закрывает свой документ без сохранения. Текущий пользовательский проект не изменяет.

Перед закрытием задачи дополнительно проверить в Revit: окно/отмену, текст/целое, недоступный параметр среди доступных, native сортировку и фильтры, скрытые поля, одинаковые значения сортировки, частичный выбор группы, вычисляемые поля группировки и сортировки, Undo и сохранение/reopen. Нужна копия рабочей спецификации и отдельная workshared-модель. Сборка и policy-тесты не дают статуса live-tested.

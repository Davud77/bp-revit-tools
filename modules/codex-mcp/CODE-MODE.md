# Code Mode в BP.Revit.AI

Code Mode — выполнение сценария над MCP-инструментами с обработкой промежуточных данных до возврата модели. Это не выполнение C# в Revit и не автоматическая атомарная транзакция.

## Два маршрута

1. **Code Mode клиента Codex:** JavaScript клиента может объединять несколько MCP-серверов. В Codex включается `features.code_mode.enabled`; `omit_tools_from = ["direct", "deferred"]` оставляет выбранный сервер в поверхности Code Mode. Поддержка зависит от клиента. [Официальная справка](https://learn.chatgpt.com/docs/config-file/config-reference).
2. **Code Mode сервера BP:** работает через стандартный MCP и с другими клиентами. `BP_REVIT_AI_TOOL_MODE=code` публикует пять инструментов: `revit_ping`, `get_project_info`, `search_tools`, `describe_tools`, `execute_code`. Полный набор предметных команд остаётся в серверном реестре. `full` по умолчанию сохраняет прежние 151 имя и добавляет три инструмента Code Mode: всего 154.

Сервер BP не получает доступа к другим MCP-серверам клиента: для этого нужен первый маршрут. Эти маршруты можно сочетать.

## Настройка

В существующую запись MCP добавьте переменную среды, сохранив действующие command/args:

```toml
[mcp_servers.bp_revit_ai]
command = "node"
args = ["C:\\path\\to\\server\\src\\index.js"]
env = { BP_REVIT_AI_TOOL_MODE = "code" }
default_tools_approval_mode = "writes"
tool_timeout_sec = 320
```

После изменения перезапустите MCP/клиент. Пример: [codex-mcp.example.toml](server/codex-mcp.example.toml). Перед запуском исходников выполните `pnpm install --frozen-lockfile` в `server/`; установленный пакет содержит зависимости и WASM.

## Рабочий процесс

1. `get_project_info` — проверить документ.
2. `search_tools` — найти операции; поиск по всем словам имени/описания, есть offset/limit/nextOffset.
3. `describe_tools` — получить точные входные схемы выбранных команд. Схема JSON не выражает все Zod refinements; они дополнительно исполняются при каждом вызове.
4. `execute_code` — передать JavaScript и явный список `toolNames`.

```json
{
  "toolNames": ["list_rooms"],
  "code": "let area = 0, count = 0; for (let offset = 0; ; offset += 500) { const page = await tools.call('list_rooms', {offset, limit: 500}); area += page.rooms.reduce((sum, r) => sum + r.areaSquareMeters, 0); count += page.rooms.length; if (!page.hasMore) break; } return {count, areaSquareMeters: area};"
}
```

Промежуточные страницы остаются в интерпретаторе. Ответ содержит только `result`, явно выбранные `logs`, имена/статусы вызовов и длительность. `print(...)` — ограниченный явный вывод. Метаданные результата предоставляются как `structuredContent` и совместимый text.

## Запись и ограничения

JavaScript исполняется в QuickJS/WASM без Node, process, require, filesystem, fetch или загрузчика модулей. Передаются только JSON-данные. Отсутствуют прямой Revit API, C# и доступ к токену моста. [Runtime](server/src/code-runtime.js).

- Каждый вызов проходит ту же Zod-схему и тот же нативный обработчик, что прямой MCP.
- Для записи нужны существующие preview/apply и planId. Привязка к документу/ревизии, срок действия, подтверждение в Revit и allowDependentDeletion продолжают действовать.
- Даже `Promise.all` исполняет вызовы последовательно, чтобы изменения не гонялись друг с другом.
- Скрипт не объединяет изменения в одну транзакцию. Если третья команда завершилась ошибкой, первые две могли сохраниться. `failed` и `effectsPossible` не являются доказательством отката. Не повторяйте запись автоматически после неясного результата.
- Объявление `execute_code` консервативно имеет readOnlyHint=false и destructiveHint=true: скрипт может вызвать операцию удаления. Политика клиента применяется к этому внешнему вызову; отдельные вложенные команды не превращаются в отдельные MCP-вызовы клиента.
- Серверная политика `BP_REVIT_AI_DENIED_TOOLS=apply_delete_plan,apply_save_project` исключает команды из прямого каталога, обнаружения и исполнения. Неизвестное имя запрета останавливает запуск. Клиентское `disabled_tools` для предметной команды само по себе не является запретом вложенного вызова — используйте серверную политику.
- Лимиты: код 32 000 символов, до 20 разрешённых команд, до 100 вызовов, до 310 секунд общего времени (30 секунд по умолчанию), 1 секунда CPU гостевого кода, 64 MiB гостевой памяти, 64 KiB результата, 8 KiB print. Не более двух одновременных сценариев. Ожидание Revit не расходует CPU гостевого кода.
- Отмена и тайм-аут прерывают гостевой код и передают AbortSignal мосту. Отмена после уже состоявшегося commit не отменяет запись. Очередь ещё не начатых вложенных вызовов не исполняется после отмены.

## Проверки

`node --test test/*.test.js` в `server/` проверяет реальный MCP stdio, компактный каталог, обнаружение схем, серверный запрет, изоляцию, CPU/память/время/вывод, отмену, пагинацию и Zod-валидацию, включая план записи на mock-обработчике.

Для проверки только чтения открытого Revit:

```powershell
node modules/codex-mcp/server/verify-code-mode.mjs 'Выходные данные/Проверки/CodeMode/live-read.json'
```

Сценарий читает проект, помещения и все стены страницами по 10 элементов, проверяет полноту и возвращает только сводку. Файл содержит сведения о текущем проекте и остаётся вне Git. Проверки записи через новый JavaScript-маршрут в живом Revit этим сценарием не выполняются.

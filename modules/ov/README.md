# HeatLossViewer — Revit 2026

Реализованы лента Revit, извлечение помещений и ограждений, окна/двери, геометрические вырезы в стенах и интерактивный HTML с бета-расчётом теплопотерь. Светлая/тёмная темы, компоновка расчётного листа, таблица, карточка и итоги ориентированы на `reference.html` и [референс](https://dunaevai.ru/materials/heat-loss).

## Сборка и установка

Требуются Revit 2026 x64 и .NET SDK 8.0. NuGet-пакетов нет. `global.json` выбирает SDK 8.0; проект — `net8.0-windows`.

```powershell
cd C:\Users\davud\Documents\HeatLossViewer
dotnet build .\HeatLossViewer\HeatLossViewer.csproj -c Release
.\Install.ps1 -SkipBuild
```

Если Revit находится в другой папке:

```powershell
.\Install.ps1 -RevitInstallDir 'D:\Autodesk\Revit 2026'
```

Скрипт устанавливает сборку в `%AppData%\Autodesk\Revit\Addins\2026\HeatLossViewer\versions\<hash>`, записывает в манифест абсолютный путь и сохраняет его в `Addins\2026\HeatLossViewer.addin`. Версионные папки позволяют обновлять установку при открытой старой сборке. Новая версия загрузится в следующем сеансе Revit. Файлы Autodesk API не копируются.

В исходном `HeatLossViewer.addin` указан относительный путь `HeatLossViewer\HeatLossViewer.dll`: для ручной установки скопируйте манифест в `Addins\2026`, а файлы сборки — в подпапку `HeatLossViewer`. Автоматический установщик формирует другой, абсолютный путь сам.

Откройте проект и нажмите **Теплопотери ИИ → Экспорт и 3D → Выгрузить 3D-модель**.

## Результат

В системной папке «Документы» пользователя создаётся `RevitHeatLossExport`:

- `building.json` — контракт для будущего Python-модуля;
- `heat_loss_viewer.html` — один HTML с данными, CSS и JavaScript внутри.

Повторный экспорт заменяет эти два файла. HTML открывается браузером по умолчанию и работает через `file://`, без сервера. Three.js 0.160.0 и OrbitControls загружаются с unpkg.com через importmap: **для 3D нужен Интернет**. Если CDN или WebGL недоступны, остаются поиск, таблица и карточки, а причина показывается над сценой. Файл не содержит запросов на отправку геометрии.

Управление: ЛКМ — вращение, ПКМ — панорама, колесо — масштаб; нажатие по объёму выбирает помещение. Таблица поддерживает выбор мышью и клавишами Enter/Пробел. Цвет — площадь, объём или уровень; срез — все уровни, до выбранной отметки включительно или один конкретный уровень. Поиск ограничивает таблицу текущего среза. Выбор скрытого срезом помещения сбрасывается. «Общий вид» и «Сверху» кадрируют текущий срез; «К выбранному» кадрирует помещение.

## Геометрический контракт 1.1

Корень: `schemaVersion`, `projectName`, `exportedAt` (ISO 8601 с часовым поясом), `coordinateSystem`, `units`, `totalRooms`, `totalBoundaries`, `rooms`, `openings`, `warnings`.

Каждое помещение содержит все требуемые поля `id`, `number`, `name`, `levelName`, `elevation`, `area`, `volume`, `height`, `contour`, `boundariesCount`, а также:

- `idText` — точная десятичная строка 64-битного ElementId для JavaScript;
- `key` — путь экземпляров связей + UniqueId помещения;
- `sourceDocument`, `sourceInstance`, `levelKey` — происхождение и идентификатор уровня;
- `baseElevation` — фактическая отметка плоскости нижнего контура;
- `heightSource` — `volume/area` либо `unboundedHeight`;
- `polygons: [{contour: [[x,y], …], holes: [[[x,y], …], …]}]` — все внешние области и их отверстия.

Единицы: метры, м², м³. Координаты — внутренняя система активного документа, Z вверх. Каждая точка связи преобразована через `GetTotalTransform()`, для вложенных связей трансформации перемножаются. `elevation` — преобразованная `Level.ProjectElevation`, независимо от настройки базы отметки уровня; `baseElevation` учитывает нижнее смещение помещения. Браузер центрирует координаты для точности WebGL, исходный JSON не смещается.

`contour` — крупнейшее внешнее кольцо для совместимости с простыми потребителями. Для полноценного расчёта используйте `polygons`. Кольца не повторяют начальную точку в конце. Кривые тесселируются API. Число ограждений — сумма исходных BoundarySegment всех колец, а не число сторон после тесселяции. Числа не округляются до вычисления высоты.

Если Revit не вычислил объём, экспортируется исходное нулевое значение, высота берётся из `UnboundedHeight`, добавляется замечание. В бета-расчёте объём воздуха заменяется на `area × height`; в карточке исходный объём остаётся «демо».

`rooms[].surfaces` содержит площади поверхностей комнат по SpatialElementGeometryCalculator. Для плоской физической стены создаётся тонкое сечение границы помещения, пересекается с фактическим Solid стены, а разность даёт объединённые вырезы. Так учитываются окна, двери, Opening, вырезы семейств и изменения профиля, представленные в геометрии стены, без повторного вычитания пересекающихся отверстий. Проверяется баланс `grossArea = netArea + Σ(cuts.area)` с допуском 0,01 м². `triangles` — чистая поверхность стены для 3D; `cuts[].triangles` — фактические контуры заполнений. Если геометрическая операция недоступна, источник площади явно отмечен `room-face-cut-fallback-beta`; используются исходная поверхность и аппроксимация по параметрам семейства. Для виртуальных границ помещений физического Solid нет.

`openings` содержит уникальные экземпляры окон и дверей (включая импортированные, не привязанные к стене), их ElementId, размеры, положение, направления, `hostKey`, `roomKeys`, `surfaceKeys`, источник аппроксимации. Нераспознанный вырез остаётся `kind: cut`, а не превращается в окно/дверь по догадке.

## Бета-расчёт

На вкладке «Исходные данные» редактируются температуры, U либо R и кратность воздухообмена. Стартовые значения — **демонстрационные**, не климатические характеристики Абакана или другого города:

| Параметр | Демо-значение |
|---|---:|
| Внутри / снаружи / под полом | +20 / −25 / +5 °C |
| Воздухообмен | 0,5 1/ч |
| U стены / окна / двери | 0,28 / 1,1 / 1,5 Вт/(м²·К) |
| U покрытия / пола | 0,2 / 0,3 Вт/(м²·К) |

Формулы: `Qогр = Σ(U × Aнетто × ΔT)`; `Qвозд = 0,33 × n × V × ΔT`; `Qитого = Qогр + Qвозд`. U = 1/R. Отрицательная ΔT принимается равной нулю. Внутренние поверхности исключаются; для нижнего ограждения применяется температура под полом. Для измеренной геометрии окна и двери считаются по площади фактического выреза. Номинальная площадь семейства второй раз не вычитается.

В карточке можно переопределить границу и U каждой поверхности, U конкретного выреза, температуру/воздухообмен помещения. Вырез без распознанного заполнения не получает выдуманное U: результат помещения показывается «демо» до уточнения. Неполные помещения исключаются из общего итога; сводка показывает охват и слово «часть». Это предотвращает принятие неизвестных потерь за нулевые. U для незаполненного открытого проёма само по себе не заменяет расчёт воздушного перетока.

Кнопка «Скачать расчёт JSON» сохраняет `heat_loss_results.json`: исходные данные, переопределения, статус demo/beta, составляющие по поверхностям и список недостающих данных. Ключи совместимы с геометрическим JSON для будущего Python-модуля. Настройки текущего экспорта сохраняются в браузере; тему можно переключать независимо от модели. Есть загрузка сохранённых исходных данных из JSON.

## Ограничения

- Сначала используются все Room с `Area > 0` активного документа. Только при их отсутствии обходятся все загруженные экземпляры связей и доступные вложенные связи. Незагруженные связи записываются в замечания.
- Коллектор не фильтрует помещения по стадии активного вида. В моделях с несколькими стадиями могут присутствовать совпадающие объёмы разных стадий.
- Высота `volume/area` — средняя; основания и верхние грани объёмов отображаются призмами. Боковые стены используют чистые поверхности из Revit, когда они доступны. Геометрические вырезы не заменяют нормативную проверку тепловой оболочки.
- Классификация наружных поверхностей по функции стены и соседним помещениям, а верхних/нижних поверхностей по положению в модели — предварительная. В неполной модели отсутствие соседнего помещения не доказывает наружную границу. Эти допущения отмечены demo/beta и доступны для исправления.
- Нет расчёта тепловых мостов, нормативной инфильтрации, ориентационных добавок, внутренних теплопоступлений и рекуперации; внутренние перетоки не моделируются. Это бета-оценка, не проектный расчёт по СП.
- Для сложных/криволинейных стен, витражей и проблемных булевых операций возможна аппроксимация. Источник площади хранится у каждой поверхности; такие случаи нельзя считать подтверждённым точным обмером всех вырезов.
- Горизонтальные повороты, переносы и зеркальные связи поддерживаются. Связи с наклоном или переворотом вертикальной оси пропускаются с объяснением.
- Стыки контуров допускаются в пределах `Application.ShortCurveTolerance`; больший разрыв вызывает пропуск помещения с указанием размера зазора. Самопересекающиеся кольца автоматически не исправляются.
- Кнопка не изменяет исходный документ и не включает расчёт объёмов в настройках модели.

## Подбор радиаторов

Вкладка «Подбор радиаторов» подбирает приборы по нагрузке помещения, температурному графику, доступной длине и высоте, зазорам и перекрытию окна. Поддержаны настенный, напольный, вертикальный и внутрипольный варианты. Для внутрипольных приборов необходимо добавить характеристики изготовителя и глубину ниши: выдуманных мощностей в каталоге нет. Предложения видны в 3D и выгружаются в JSON и CSV. Семейства в исходный RVT пока не устанавливаются.

Использовано 2 550 позиций из предоставленного файла «Радиаторы керми мощность.xls». Мощность пересчитывается через логарифмический температурный напор и показатель n из таблицы. Пользователь может задать нагрузку помещения вручную или явно сопоставить её с одной из 258 строк PDF. Номера помещений PDF и Revit различаются, поэтому автоматического соединения по номеру нет. Подробнее: [методика, нормативные правила и материалы](docs/RadiatorSelection.md).

Для комнат без окон предлагаются места у наружных стен. Стеновые вырезы, двери, доступная высота и столкновения приборов проверяются по экспортированной геометрии. Тамбуры с наружными дверями блокируются; лестницы и вероятные пути эвакуации требуют проверки проектировщиком. Геометрия приборов схематическая, размеры креплений и окончательные зазоры уточняются по документации изготовителя.

На «Блоке 5» при стартовых демо-нагрузках и графике 70/55 °C: 105 помещений получили 115 предложенных приборов; 11 требуют проверки ограничений, 18 — исходных данных, в 8 не хватает мощности или доступного места. Это бета-предложение, а не завершённая рабочая расстановка. Отчёты: `artifacts/radiator-model-audit.json`, `artifacts/radiator-browser-report.json`.

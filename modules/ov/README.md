# ОВ для BotPlus RT

Модуль HeatLossViewer входит в [единый установщик](../../docs/INSTALLATION.md). В Revit откройте **BotPlus RT → ОВ**. Рабочие сценарии описаны в [руководстве](../../USAGE.md#ов), методика расчёта — в [POTERI.md](docs/POTERI.md), подбор приборов — в [RadiatorSelection.md](docs/RadiatorSelection.md).

Экспорт записывает `building.json` и `heat_loss_viewer.html` в `Документы/RevitHeatLossExport`. Повторный экспорт заменяет эти файлы. HTML открывается локально. Для 3D нужны WebGL и доступ к CDN Three.js. Таблицы, поиск и карточки доступны без 3D.

Клиент расчёта получает `building.json`, проверяет `schemaVersion` и возвращает результаты, привязанные к `room.key`. Не следует связывать результаты только по `id`: один ElementId может встречаться в нескольких экземплярах связей.

## Геометрический контракт 1.1

Корень: `schemaVersion`, `projectName`, `exportedAt` (ISO 8601 с часовым поясом), `coordinateSystem`, `units`, `totalRooms`, `totalBoundaries`, `rooms`, `openings`, `warnings`.

Каждое помещение содержит все требуемые поля `id`, `number`, `name`, `levelName`, `elevation`, `area`, `volume`, `height`, `contour`, `boundariesCount`, а также:

- `idText` — точная десятичная строка 64-битного ElementId для JavaScript;
- `key` — путь экземпляров связей + UniqueId помещения;
- `sourceDocument`, `sourceInstance`, `levelKey` — происхождение и идентификатор уровня;
- `baseElevation` — фактическая отметка плоскости нижнего контура;
- `heightSource` — `volume/area` либо `unboundedHeight`;
- `polygons: [{contour: [[x,y], …], holes: [[[x,y], …], …]}]` — все внешние области и их отверстия.

Единицы: метры, м², м³. Координаты — внутренняя система активного документа, Z вверх. Каждая точка связи преобразована через `GetTotalTransform()`, для вложенных связей трансформации перемножаются. `elevation` — преобразованная `Level.ProjectElevation`, независимо от настройки базы отметки уровня; `baseElevation` учитывает нижнее смещение помещения. Браузер центрирует координаты для точности WebGL, исходный JSON не смещается.

`contour` — крупнейшее внешнее кольцо для совместимости с простыми потребителями. Для полноценного расчёта используйте `polygons`. Кольца не повторяют начальную точку в конце. Кривые тесселируются API. Число ограждений — сумма исходных BoundarySegment всех колец, а не число сторон после тесселяции. Числа не округляются до вычисления высоты.

Если Revit не вычислил объём, экспортируется исходное нулевое значение, высота берётся из `UnboundedHeight`, добавляется замечание. Исходный объём и оценочная высота хранятся отдельно.

`rooms[].surfaces` содержит площади поверхностей комнат по SpatialElementGeometryCalculator. Для плоской физической стены создаётся тонкое сечение границы помещения, пересекается с фактическим Solid стены, а разность даёт объединённые вырезы. Так учитываются окна, двери, Opening, вырезы семейств и изменения профиля, представленные в геометрии стены, без повторного вычитания пересекающихся отверстий. Проверяется баланс `grossArea = netArea + Σ(cuts.area)` с допуском 0,01 м². `triangles` — чистая поверхность стены для 3D; `cuts[].triangles` — фактические контуры заполнений. Если геометрическая операция недоступна, источник площади явно отмечен `room-face-cut-fallback-beta`; используются исходная поверхность и аппроксимация по параметрам семейства. Для виртуальных границ помещений физического Solid нет.

`openings` содержит уникальные экземпляры окон и дверей (включая импортированные, не привязанные к стене), их ElementId, размеры, положение, направления, `hostKey`, `roomKeys`, `surfaceKeys`, источник аппроксимации. Нераспознанный вырез остаётся `kind: cut`, а не превращается в окно/дверь по догадке.

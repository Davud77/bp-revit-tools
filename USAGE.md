# Как пользоваться BotPlus RT

Начиная с 1.4 окна и двери, не связанные ни с одним выгружаемым расчётным помещением, исключаются из JSON / HTML ОВ и подбора. Исходные элементы Revit сохраняются; число исключений записывается в предупреждения выгрузки.

Revit 2026, вкладка **BotPlus RT**. Панели: **MCP**, **Ac2Revit**, **ОВ**, **Отверстия**, **Марки**, **Сервис**.

## Перенос из Archicad

1. Откройте сохранённый PLN в Archicad с Tapir. Во время экспорта не редактируйте модель.
2. Нажмите **Archicad → Revit** либо **Экспорт Archicad**. Подключитесь к порту нужного экземпляра Archicad. Если открыто несколько экземпляров, у них разные порты; в окне показаны порт, путь проекта и тип активного окна.
3. Выберите формат и раскройте **Элементы экспорта**. Все категории включены по умолчанию.
4. Для IFC выберите транслятор, сохраняющий координаты и идентичность объектов. Начните экспорт.
5. Итоговые файлы лежат в подпапке `export` нового сеанса. Комбинированный режим также создаёт `pipeline.json` для сборки.

| Формат | Результат | Построение в Revit |
| --- | --- | --- |
| Только JSON | `export/manifest.json`, `mapping.json`; IFC не вызывается | Нативные адаптеры JSON. Сложные формы и несопоставленные семейства могут остаться неподдержанными; результат отражён в отчёте. |
| Только IFC | `export/model.ifc`; подробный JSON и этапы геометрии не подготавливаются | Открывайте IFC штатной командой Revit **Файл → Открыть → IFC**. |
| JSON + IFC | Оба итоговых файла, проверенный исходный снимок и pipeline | JSON передаёт параметры и связи, IFC обеспечивает геометрические адаптеры и проверки. |

Выбор категорий управляет итоговыми файлами и новым построением. Служебный исходный снимок может содержать другие категории: он нужен для координат, хостов, вырезов и проверки восстановления. Ограничение экспорта сохраняется в pipeline и не снимается последующим выбором категорий импорта. Флажки не удаляют ранее созданные объекты Revit.

Если в JSON нужны двери или окна, включите также их стены. Если хост исключён, объект отмечается как неподдержанный; транслятор не придумывает стену. Исключение заполнений из IFC сохраняет исходные вырезы в оставленных стенах. Для помещений важны все исходные ограждения: исключение категорий может нарушить замыкание или проверку площади. Оси в текущем комбинированном режиме извлекаются из IFC; JSON-only не создаёт отсутствующие в JSON оси.

## Продолжение после отказа IFC

Код `-2130313109` — `APIERR_BADWINDOW`: Archicad не допускает сохранение из текущего окна. Начиная с 1.2.0 процесс сам открывает план перед IFC; при таком отказе переключается в 3D и делает один повтор с тем же транслятором и охватом всего проекта. Если повтор не помог, сохраняет диагностику и прекращает сеанс без публикации неполного результата.

Для старого сеанса нажмите **Продолжить сеанс**, выберите его `session.json` и оставьте открытым тот же PLN. Если исходная модель изменилась, начните новый экспорт. При нескольких Archicad проверьте порт — одинаковый путь PLN не означает одинаковое несохранённое состояние двух экземпляров.

## MCP и ОВ

В MCP сначала прочитайте проект через `get_project_info`. Для записи используйте пару `preview_*` → `apply_*` с выданным `planId`. Имя подключения остаётся `weam_revit_ai`; смена надписи панели не требует перенастройки клиента. Локальные данные остаются в `%LOCALAPPDATA%/WEAM.Revit.AI`.

Просмотрщик ОВ работает с пригодными контурами и площадями помещений. Проверяйте предупреждения, исходные температуры, конструкции и параметры приборов. Наличие HTML и расчёта не заменяет инженерную проверку проекта.

### Изменения 1.3.0

- **Сетки Archicad:** для нативного переноса нужен Tapir 1.8.0 или новее с `Get3DGeometryOfElements`. JSON хранит подготовленные поверхности и ссылки на архив API. Передаются контуры, отверстия, отметки и материалы поверхности. Сетка со ступенью, где одному XY соответствуют две высоты, разделяется на несколько топотел с общей исходной идентичностью. Поверхность проверяется по полному пересечению треугольников; неподтверждённый результат откатывается. Редактируемые топотела создаются и в режиме JSON без IFC. Старые экспорты без 3D-геометрии требуют нового сеанса.
- **Помещения:** передаются исходные нижняя/верхняя привязки и смещения, включается вычисление объёмов. Отчёт `ZoneVerticals` сравнивает параметры и фактический объём с пространственным телом Revit. Отсутствие исходной связи не заменяется догадкой о следующем этаже.
- **Расчёт ОВ:** Poteri выбирается в «Исходных данных». Параметры наследуются от здания к этажу и помещению; отдельная конструкция имеет свои U/слои и коэффициенты. Пустое поле снимает переопределение. Подробности: [POTERI.md](modules/ov/docs/POTERI.md).
- **Выделение в ОВ:** обычный клик выбирает один объект, Ctrl + клик добавляет, Shift + клик снимает, Esc очищает. Работает в таблице и в 3D для помещений, заполнений и приборов. Карточка показывает последний активный объект.
- **Проёмы ОВ:** экспортируются двери/окна, нативные пустые проёмы и распознанные вырезы стен без семейства. Исходная категория имеет приоритет; для неизвестного пустого проёма тип предварительно определяется по высоте низа и требует проверки. Вырез и его заполнение не считаются дважды. Проёмы без помещения сохраняются в JSON и 3D, но не добавляются к тепловому балансу произвольного помещения. `openingCoverage` и предупреждения показывают охват. Двери красные (`#ff0000`) в обеих темах.
- **Отображение ОВ:** повторные совпадающие грани получают одного видимого владельца, нормали приведены к общей ориентации; при скрытии владельца отображается следующий. Исправлены наложения соседних объёмов и параметры глубины. Геометрия Revit при этом не меняется.

Результаты фактических проверок и ограничения: [docs/VALIDATION.md](docs/VALIDATION.md). Следующие работы: [ROADMAP.md](ROADMAP.md).

## Библиотека ОВ и радиаторы

Откройте **BotPlus RT → ОВ → Библиотека**. Вкладки «Материалы», «Стены», «Перекрытия», «Полы по грунту», «Окна» и «Двери» заполняются из Revit и загруженных связей. Поиск работает по названию / ElementId. Можно задать λ, плотность и теплоёмкость материалов, включить параметры типа в расчёт, выбрать слои или R₀. Полы по грунту сначала явно отметьте на вкладке «Перекрытия».

**ОВ → Радиаторы** открывает подбор в том же окне: температурный график, правила размещения, каталог Kermi, свои приборы и импорт JSON, индивидуальные нагрузки, ручное сопоставление PDF, 3D и ведомости JSON / CSV. Нажмите «Сохранить в модели», затем сохраните RVT. «Отмена» отменяет изменения окна. В экспортированном HTML остаются результаты подбора и 3D; редактирование выполняется в Revit.

Для материалов связей сохраняются переопределения в текущем проекте. Толщины конструкций меняются штатными средствами Revit. Подбор остаётся предварительной схемой; семейства радиаторов автоматически не размещаются.


## Просмотрщик ОВ 1.4.1

В шапке: «3D и помещения», «Итоги», «Логи», скачивание расчёта JSON и смена темы. В «Итогах» находятся сводка, этажные суммы, общий список помещений с поиском / фильтрами и «Печать / PDF». В «Логах» — замечания экспорта. Нулевой список проёмов без помещений скрыт. На ленте ОВ порядок: сведения о проекте → выгрузка 3D → библиотека → радиаторы.


## Таблицы исходных данных и просмотрщик 1.5

В «Сведения о проекте → Исходные данные → Этажи / Помещения» параметры вводятся в ячейки таблицы. Пустая ячейка возвращает наследование. Точка и запятая допустимы; ошибочное число блокирует сохранение. Клик по заголовку сортирует строки.

В просмотрщике «Печать / PDF» находится в шапке, перед скачиванием JSON. Заголовки таблиц ограждений, проёмов, приборов и этажных итогов сортируют строки по возрастанию / убыванию; доступны Enter и пробел. Пустые значения остаются внизу. После пересчёта выбранная сортировка сохраняется.


## Изменения 1.6

В общем переносе Archicad → Revit флажок «Рельеф Mesh → Топотело» включён по умолчанию, в том числе в окне выбора категорий импорта. Он управляет этапом создания нативных Toposolid. Для прямого чтения сеток нужен Tapir 1.8+; установщик предлагает нужную версию Archicad. После обновления Tapir перезапустите Archicad и выполните новый экспорт: старый снимок без подготовленной поверхности сам не обновляется.

В окне переноса поле «Файл импортируемой модели RVT» задаёт полный путь; «Обзор…» открывает выбор имени и папки. Существующий RVT не перезаписывается. Поле действует при сборке в новом проекте; для текущего проекта сохраняется его существующий путь. Выбранные шаблон и выходной путь сохраняются в сеансе подготовки.

Журналы рядом с сохранённым RVT: `Имя.botplus-import.log` — сводка по категориям и по каждому исходному GUID; `Имя.botplus-import.json` — машинная инвентаризация, класс и ID представления Revit, результаты этапов. Они обновляются при сохранении и сохранении с новым именем. Контрольные точки могут содержать ещё неперенесённые элементы — это текущая инвентаризация, а не сообщение о завершении.

«Сервис → Обновления»: проверить стабильный релиз, скачать с прогрессом и проверить SHA-256, открыть установщик. Перед самой установкой сохраните модели и закройте Revit. Проверка обновлений не закрывает модели. Если релизов нет, файл отсутствует или контрольная сумма неверна, установщик не запускается.
